# 评估方法说明文档（Evaluation Methodology）

本文件说明针对「论文结构化阅读助手」这一开放场景所设计的**自定义评估方法**：评估维度、可操作判定锚点、整体分计算、为何采用「规则 + LLM-as-judge」混合范式，以及如何验证该方法的有效性。

---

## 1. 场景与为什么需要自定义评估

任务书要求评估**不存在唯一标准答案**的开放场景产物。论文阅读助手的输出是「结构化笔记」，质量不能靠字符串匹配判定，也不能用「较好地满足要求」这类无依据表述。因此本方法：

- 将质量拆成 **6 个可独立打分的维度**；
- 每个维度给出 **0–5 分的可操作判定锚点**（不同评审者按锚点应能得出接近结论）；
- 采用 **规则校验 + LLM-as-judge 混合** 实现自动/半自动评测；
- 用 **判别力 / 一致性 / 对抗性** 三类实验证明方法可靠。

---

## 2. 评估维度与判定锚点（核心）

> 完整可执行定义见 `src/rubric.py`。下表为文档化摘要，所有锚点均以「可观察、可核对」的客观条件表述。

| 维度 | 类型 | 权重 | 0 分 | 5 分（标杆） |
|---|---|---|---|---|
| **事实准确性** factual_accuracy | LLM-judge | 0.25 | 大面积虚构，主体内容原文不存在 | 全部论断原文可查、零编造 |
| **要点完整度** completeness | 规则 | 0.15 | 未形成结构化笔记 | 5/5 必备板块齐全且含关键子要点 |
| **证据可追溯性** traceability | 规则 | 0.20 | 几乎零重叠，脱离原文 | ≥90% 句子可映射回原文（trace_ratio≥0.9） |
| **专业术语正确性** terminology | LLM-judge | 0.15 | 术语普遍错误 | 缩写/术语使用准确，映射正确 |
| **格式规范性** format | 规则 | 0.10 | 无结构化标题 | 5/5 一级标题齐全、分点清晰 |
| **可读性** readability | LLM-judge | 0.15 | 语义混乱不可读 | 通顺连贯、重点突出 |

**必备板块（完整性 / 格式校验基准）**：①研究目标 ②核心方法 ③主要创新点 ④实验结果与分析 ⑤存在不足与未来方向。

**整体分公式**：`overall = Σ(维度分 × 权重)`，范围 0–5，保留两位小数。

**等级映射**：≥4.5 优(A) / ≥3.5 良(B) / ≥2.5 中(C) / ≥1.5 差(D) / 其余 劣(F)。

**锚点设计原则**：以「可观察事实」为准。例如事实准确性 3 分的判定是「约 75–90% 论断可溯源，1–2 处概括性偏差（如把『相对提升约 65%』写成『提升 65%』），无核心结论被歪曲」——明确到可直接核对，避免模糊。

### 可追溯性规则（启发式代理）
对笔记非标题句，计算句中**实体/数字/术语**在原文中出现的比例，取全笔记均值 `trace_ratio`，再按阈值映射到 0–5。这是「论断能否映射回原文」的可复现代理指标。

## 3. 为什么是「规则 + LLM-as-judge」混合

| 维度 | 选型 | 设计依据 |
|---|---|---|
| 完整度 / 格式 | **规则** | 是否为「5 板块 + 分点 markdown」可由正则确定性判定，零随机、可复现、可解释，无需消耗模型调用。 |
| 可追溯性 | **规则** | 论断与原文的信号重叠率可用词/数字匹配量化，作为可解释代理指标。 |
| 事实准确性 / 术语 / 可读性 | **LLM-as-judge** | 这三类需语义理解（是否编造、术语是否张冠李戴、行文是否通顺），规则难以覆盖，交给 Hy3 充当裁判，并给出明确 checklist 约束判定。 |

**混合的优势**
1. **可复现**：规则部分零方差，保证整体评估稳定；
2. **可解释**：规则给出命中板块数、trace_ratio 等硬证据；
3. **省成本**：6 维中 3 维不调模型，仅 3 维用 judge；
4. **无密钥降级**：当未配置 Hy3 时，judge 维度退化为保守规则分（不崩溃），保证脚本在任意环境可运行。

**LLM-as-judge 的约束**：judge 提示词内置逐维度 checklist（如「逐条核对笔记里的具体数字是否与原文一致」「核对方法名有无张冠李戴」），并要求只返回标准 JSON，降低裁判随意性。

## 4. 有效性验证（如何证明方法可靠）

| 验证项 | 做法 | 通过判据 |
|---|---|---|
| **判别力** | 用 good/medium/bad 三档候选笔记，看评估分能否正确排序 | Spearman(评估, 专家) 显著正相关；good>medium>bad 单调成立 |
| **一致性** | 同一笔记重复评 5 次；并与 human_labels.json 专家标注对比 | 规则维度 std=0；与专家整体分 Spearman 高 |
| **对抗性** | adv_jargon（堆术语）/ adv_cite（伪造引用）/ adv_padding（注水）三样本 | 评估方法不被「篇幅/术语/伪造引用」骗取高分，应给出低/中分并标注问题 |

> 三项实验脚本与真实结果见 `results/validation_*.json` 与 `report/analysis_report.md` 第 4–5 节。

---

## 5. 如何运行评测

```bash
# 0) 配置 .env（API_KEY / BASE_URL / MODEL_NAME）
# 1) 完整评测（生成笔记 + 6 维打分，输出 result_table.csv / summary.json / case_analysis.md）
python eval/run_eval.py

# 2) 三项有效性验证
python eval/validate_discrimination.py
python eval/validate_consistency.py
python eval/validate_adversarial.py

# 3) 生成结果图表（SVG）
python eval/make_charts.py
```

**实现要点（与 Hy3 接口的适配）**：Hy3 为推理模型，可能把预算消耗在 `reasoning_content` 上导致 `content` 为空。客户端 `src/client.py` 在 `content` 为空时按「token 受限」重试并逐次翻倍 `max_tokens`，并配合系统提示要求「直接给最终笔记、勿展开思考」，确保稳定拿到输出。
